# 验证规则

本地默认只进行语法解析。类型检查、测试和构建在 GitHub 托管 runner 执行。

## 首期交付范围

知枝 Next 首期将核心能力集中在云端 CLI 和知识服务。Web 与安卓对接同一套服务。当前纳入 CI 和构建的是 Linux 后端 `backend`、学习 Web `learning-web`、私有 Wiki `wiki-private` 及现有服务端 Agent 适配 `pi-zhizhi`。后端产物是带学习 Web 静态资源的 wheel，构建完成后实际安装并检查 CLI 和知识服务的命令入口。

安卓客户端及轻量桌面 Git 采集器尚无可构建工程。CI 中的共享 API 验证覆盖的是现有服务，安卓设备验收待客户端接入后执行。

原知枝仓库只保留历史引用。归档资料、完整 Electron 应用、独立公开站、第三方聊天中转、独立工具及旧交付验收可以供追溯或单独回归，不进入首期发布门槛。

## 日常检查与完整回归

`ci.yml` 为 PR 和 main 推送执行标准检查。`Required checks` 始终汇总计划要求的任务，成功需要所选任务实际通过。main 分支保护依赖这个任务名。

| 变更或入口 | 执行范围 |
|---|---|
| 仅文档、历史归档、退役应用或可选组件 | 仓库元数据检查。归档、迁移资料和退役目录的链接目标不参与发布门槛 |
| 学习 Web、私有 Wiki、Pi 适配 | 所属组件的类型与单元检查。Pi 适配同时运行 Python / TypeScript 协议组合 |
| 后端、云端部署代码、共享知识契约 | 四个首期组件及 Agent 协议，检查 CLI 和知识服务入口，执行后端单元和隔离集成 |
| CI、共享脚本或首期工具链配置 | 四个首期组件的标准检查 |
| 手动 `profile=standard` | 四个首期组件的 Linux 标准检查 |
| 手动 `profile=full` | 加跑两个 Web 客户端的合成交互，以及 Web 和 Pi 适配构建 |

后端隔离集成包括真实本地 HTTP、Git、SQLite 和服务进程重启，模型与外部账号使用隔离 fixture 或保持禁用。后端保留在用模块的回归，历史交付套件的排除项在 `scripts/dev.ps1`。未安装 ASR 模型时相关用例如实跳过。固定时间预算的性能测试可独立验证。

平台的严格类型检查使用锁定工具链与 Next 自身基线 `a8749ee3` 比较，保留当前和基线的完整诊断并阻断新增错误。

## 证据与真实验收

| 层级 | 证明范围 |
|---|---|
| syntax / static | 代码可解析，配置与维护文档符合仓库规则 |
| unit | 所属模块在已知条件下的行为 |
| isolated integration | 临时 SQLite、Git、HTTP 和进程等真实组件的组合 |
| build / package smoke | 对应提交的产物可构建、检查或启动 |
| live acceptance | 获准账号、模型、素材和安装环境中的用户旅程 |

浏览器合成交互使用测试材料，关闭截图比对、录屏和视觉评审。真实部署、账号、模型和 Android 设备验收单独记录。报告注明源码 SHA、运行链接和通过、失败、跳过或未执行的范围。需要保存的证据上传失败时，工作流保持失败。
