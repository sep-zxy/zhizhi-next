# 验证规则

本地默认只进行语法解析，不自动进行类型、单元、集成、浏览器、构建或视觉检查。仓库检查、测试和构建在 GitHub 托管 runner 执行。

| 层级 | 证明范围 |
|---|---|
| syntax / static | 可解析、配置和文档引用符合规则 |
| unit | 所属模块的确定性行为 |
| isolated integration | 真实临时 SQLite、Git、HTTP、进程之间的组合，模型/网络可为明确 fixture |
| build / package smoke | 对应提交的真实产物能被检查或启动 |
| live acceptance | 获准真实账号、模型、素材和安装环境的用户旅程 |

上一级不能替代下一级。测试目录名包含 e2e 不提高证据等级。跳过、阻塞、取消与未运行分别记录；没有账号的 fixture 成功不证明真实模型或渠道成功。

## 日常检查与完整回归

`ci.yml` 为 PR 和 main 推送运行标准检查，其他分支只在创建 PR 后执行，避免同一提交同时触发分支推送与 PR 两轮检查。`Required checks` 始终汇总计划所需任务，失败、取消或意外跳过均不能被其他成功任务掩盖；main 分支保护依赖这个稳定任务名。

| 变更 / 入口 | 实际执行范围 |
|---|---|
| README、AGENTS、docs、决策记录与历史材料 | 仓库布局、锁文件归属、配置示例、维护文档链接和空白检查，不安装应用依赖 |
| 单个应用或可选组件 | 所属模块在 Linux 执行类型与单元检查；不会仅因前端或桌面改动重跑整个后端 |
| 后端或 Pi 集成 | 所属模块检查，并执行 Python / TypeScript 协议组合；后端保留单元与隔离集成回归 |
| 共享知识契约 | 检查后端、私有与公开 Wiki、Vault Manager、Continuity Widget 等实际消费者 |
| CI、共享脚本或工具链配置 | 所有组件的标准检查，确保检查流程本身没有漏掉模块 |
| 手动 `workflow_dispatch`，`profile=standard` | 所有组件的 Linux 标准检查 |
| 手动 `workflow_dispatch`，`profile=full` | 在标准检查上增加后端 Windows/macOS、受影响前端的合成交互、参考平台性能门禁与应用构建 |

标准检查不包含独立的浏览器旅程、跨系统全量重复回归和发行构建；learning-web 自身依赖浏览器的单元用例仍安装 Chromium 执行。public-wiki 的渲染测试需要编译 vendored 依赖，保留这个测试前置步骤。可分发安装包继续由 `build.yml` 按目标手动构建。

文档判定只针对维护文档入口和 docs / .agents / archive 目录，不会将后端运行时使用的 Markdown 提示词当成纯文档忽略。可选组件不进入主应用默认安装链，其代码变化触发独立检查。

浏览器交互测试使用合成资料；截图比对、录屏和视觉评审默认关闭。CI 保存的失败日志和测试报告只包含测试材料，不上传真实凭据、知识库或账号状态。

必须保存的产物和证据上传失败，工作流保持失败。报告须包含 source SHA、run URL、实际范围、passed/failed/skipped 和限制，不累加不同运行的通过数。

原有底座、平台和跨模块测试均保留，按上述范围选择执行层级。隔离回归没有安装 ASR 模型时如实跳过相关用例；真实 ASR 和账号验收另行执行，不删除测试或放宽断言制造全绿。

后端 pytest 保持原有测试目录，一次收集完整失败报告并输出用例进度，避免按前几个失败反复重跑整个 CI。隔离组合任务在前面的类型或单元检查失败后仍执行，汇总状态保持失败；取消或未执行的用例不计作通过。

配置测试使用 backend/tests/environment_support.py 构造同时含 HOME 和 APPDATA 的隔离环境，不继承 runner 的个人配置。明确测试缺失或空环境变量的反例仍直接传递原始环境。模拟进程使用模拟 Job Object；原生进程树清理和 Windows 句柄验证使用真实进程。

手动完整回归中的后端 macOS 检查使用官方 macos-15-intel 托管 runner（x64），避免 ARM 池持续排队阻塞平台验证。桌面手动打包仍使用 macos-15（ARM64），两者的架构证据分别报告；标签来源见 [官方 runner 清单](https://github.com/actions/runner-images#available-images)。

基准聚合脚本的解释器选择用例使用显式 fixture 验证命令与聚合契约；真实 SQLite 读路由和 Graphify 性能门禁在手动完整回归的 ubuntu-24.04 参考 runner 各执行一次，阈值保持原样。线程池固定延迟预算也只在 Linux 判断，跨平台并发完成和无死锁检查仍保留。Windows/macOS 执行兼容性与隔离集成检查，不把不同托管机器的速度当成同一性能基线。包含 50 次趋势采样的完整 run_all.sh 仍用于人工基准，不搭载于日常单元用例重复执行。

Python 平台当前存在严格类型债务。CI 用同一锁定 pyright 和解释器比较迁移基线 62397c2f 与当前源码，输出完整诊断并阻断新增错误；无新增错误不等于严格类型全清。原基线通过不可变 Git 对象重建，不维护可随意扩大的忽略清单。
