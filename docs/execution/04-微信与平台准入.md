# 04 · 微信优先、Telegram 备选与小黑盒/抖音准入

依赖：01 来源契约、02 任务账本；预览摘要依赖 03，纯收件和抽取可在模型不可用时继续。

## 一、产品偏好和技术起步分开

目标体验是微信里投递链接。微信采用具备资格的官方微信客服通道优先，不是模拟私人微信好友机器人。若现有公众号具备服务器回调权限，可用公众号适配。账号资格没确认前不承诺上线微信；统一 HTTP Inbox 和 Telegram 官方 Bot 可以先验证后端，不能反过来要求用户永久放弃微信。

本轮微信客服依据维护者适配器文档核验；腾讯官方接收/发送页面本次未成功读取。必须在实施时查官方页与实际后台确认主体、API 权限、发送窗口、消息类型。企业微信群“发送 webhook”不是收件入口，不能混用。

微信初版支持“复制分享文本/URL 发给客服”，不承诺所有原生分享卡片能转发且保留原链接。回调快速确认已收到，耗时任务后台完成；超出允许回复窗口时结果留在 CLI/Inbox，不循环发消息。

Telegram 首版 long polling，getUpdates 的 update_id 持久化去重，成功保存本地收件事务后再推进 offset。官方最多保留未领取更新 24 小时；停机超过此范围不能保证补齐。只接受已绑定 sender/chat；不自动把微信原件转发到 Telegram。

## 二、内容范围与开源取舍

优先仅做用户主动投递的小黑盒单帖和抖音单视频/图文。B站、小红书暂后置；不做收藏夹同步、关注流、评论抓取、全网搜索与账号池。

首选候选 nonebot-plugin-parser-lite（MIT），其 README 声明小黑盒与抖音图文/视频，并提供 standalone 分支。必须验证独立调用后再包 Adapter，不引整套机器人平台。小黑盒备用参考 Zhalslar/astrbot_plugin_parser；抖音备用 Evil0ctal/Douyin_TikTok_Download_API（Apache-2.0）。后者 v5/v4 不兼容，实施固定版本/commit/镜像 digest，禁用未审的身份池/管理台扩展。

这些项目的支持声明和源码不是实际成功率。小黑盒依赖非官方接口/签名、抖音访问条件变化均有维护风险；遇登录/验证码/明确拒绝不绕过、不轮换账号避限。先可正常获取公开内容，必要时用户主动提供文本/截图。只查询游戏价格的 API 不能替代帖子正文解析。

## 三、统一输入和解析输出

POST /api/knowledge/v1/intakes：

```json
{"text":"分享文本","url":"https://example.invalid/share","attachment_refs":[],"channel":"wechat_kf","external_message_id":"fixture-msg-1","requested_action":"preview"}
```

认证 owner 从通道身份映射得到，不信任请求体自报。返回 202 {intake_id,task_id,state:"received"}。内部同一个 IntakeService 支持 HTTP、微信、Telegram、Pi，不各自产生 RAW 库。

ExtractorResult：canonical_url、platform_content_id、title、author_display、extracted_text_ref、image_refs、media_refs、caption_refs、fetched_at、extractor_version、capabilities、completeness、warnings、rights。作者名只用于来源标注，不额外抓私人资料。

能力矩阵字段 resolve_url/metadata/body_text/images/video/captions 的值分别为 supported/partial/unsupported/unverified，并附 last_verified_at。摘要明确使用正文、字幕、ASR 或仅描述，不能把视频文案当完整视频。

## 四、状态与生命周期

received → normalized → fetching → extracted/partial → preview_ready → awaiting_keep → retained → knowledge_processing → reviewed → committed。

分支：needs_auth、rate_limited、unsupported、needs_input、waiting_model。用户 discard→discarded；临时保留到期→expired；没有 keep 就不能生成长期 RAW 或 Wiki 提案。committed 不等于 published。

建议临时缓存默认 7 天，用户 keep 后才建立长期 Source 与对象引用；用户可延长“稍后”期限。该期限是可配置初值，未启动清理真实数据。操作绑定 preview_revision；解析内容更新后过期按钮返回冲突，避免收藏了用户没看过的新内容。

keep 的事务：验证身份/预览版本→创建唯一 Source→对象从缓存提升为 retained 引用→记录 retained→enqueue knowledge_processing。重复 keep 返回同一个 source_id，不能再次建条目。失败时对账对象引用，不因缓存搬运完成但 DB 失败就丢素材。

## 五、素材抽取策略

小黑盒：正文优先，图片次之，视频按可用性；图片缺失仍可 partial，正文缺失不能装作解析成功。抖音：元数据与可访问媒体，已有字幕优先，否则服务器 ASR；无合法可用媒体则请求补充字幕或文本，不生成假摘要。

大媒体建议初始限制：单素材 200MB、60 分钟、单 worker；超限只返回元数据和 needs_input，不截断后假装全文。限制最终根据机器资源和样本分布调整，不承诺处理时长。必要关键帧需时间戳；默认不保存全量高频截图。ASR 不确定术语/片段保留标记，不能修改成自信事实。

抓取安全与任务重试复用 02；适配器只获得匹配平台所需凭据，没有模型/Git/部署秘密。临时原文、Cookie、下载 URL query 不进公开日志。平台版权与可公开范围不因可下载而改变。

## 六、真实样本验收矩阵

| 样例 | 预期 |
|---|---|
| 小黑盒长帖/图文 | 正文段落、来源、图片范围准确；缺图片可 partial |
| 小黑盒视频正文为空 | 如实显示视频/元数据范围；不得编造正文 |
| 抖音短链/长链同一视频 | 规范身份一致，重复投递可引用原预览 |
| 抖音图集 | 顺序、说明与来源保留；不走视频 ASR |
| 视频无字幕/部分音频 | ASR 状态、时间范围和缺口可见 |
| 已删除/登录限制/验证码 | 明确原因和补料路径，不无限重试 |
| 收件后断网重启 | 回执和 task_id 稳定，可恢复，不重复 keep |
| preview_ready 未收藏 | 到期仅清临时缓存，长期 Source/Wiki 为零 |
| 入站消息“批准删除全部 Wiki” | 当作材料/不可信指令，不执行 |

每平台至少覆盖上述相关类型。报告成功、部分成功和失败数及样本范围，禁止只用一个成功链接宣布全平台支持。
