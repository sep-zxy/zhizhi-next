# 07 · 验收、分阶段上线与故障手册

## 一、定义完成

“代码存在”“服务启动”“CI 绿”“模型能回答”均不足以验收。每个工作包必须给出输入 fixture、实际输出、测试命令、通过/失败数、环境和残余缺口。当前文档是方案，没有声称以下测试已运行。

原审计的 129 个后端测试文件/3,352 test 定义/68 个前端文件只是统计；现有 Actions 主要语法、构建和 smoke，不能拿它代替本轮领域链路测试。现有 AGENTS 要求应用构建用 GitHub 托管 Actions runner，实施必须遵守。

## 二、开发阶段与开关

| 阶段 | 输出与范围 | 进入下一阶段门槛 |
|---|---|---|
| A 契约 | 脱敏 fixtures、Schema/来源/ID、dry-run | 无字段损失、幂等、旧接口兼容 |
| B 领域骨架 | 身份、Task、outbox、对象、秘密 mock | 越权/重放/重启测试通过 |
| C 学习闭环 | 知枝→提案→AI/人工审查→fixture Git | CAS、崩溃恢复、个人表达不伪造 |
| D 收件闭环 | HTTP、Telegram、条件微信；小黑盒抖音 | 真实样本报告、preview→keep 不可绕过 |
| E 小范围真实运行 | 一份批准的测试库，受限订阅账号 | auth/额度/用量、恢复、数据路由验证 |
| F 自动增量 | 少量已收藏来源，正式写入开关 | 影子报告与误判审计通过后明确启用 |
| G 公开投影 | 指定公开范围的 staging/站点 | 隐私/版权/资源清单与无模型构建验收 |
| H 雷达 | 推荐→接受→学习→回填 | 不伪掌握、不重复任务、不覆盖用户内容 |

关键开关独立：intake_enabled、model_processing_enabled、auto_commit_enabled、publish_enabled、radar_enabled、metered_api_enabled。初始 auto_commit/publish/metered_api 全 false。开关是在获准实施后配置，不在本轮擅自改生产。

影子运行：提案可生成但不应用，比较它建议改哪里、是否本应升级用户、来源能否支持；记录错误类型后调策略，不让用户审几百条低风险样本。不能以影子运行产物暗中写真实 Vault。

## 三、端到端验收矩阵

| ID | Given / When | Then |
|---|---|---|

## 四、监测指标只服务排障

记录任务各阶段耗时、queue_age、失败原因、waiting_auth/quota 数、重试次数、提案 no_change/needs_evidence/needs_user 数、Git stale 数、索引 revision lag、公开排除原因数量。用这些定位堵点，不宣称“条目越多学习越好”。

日志统一 trace_id/task_id/change_id，正文和 token 默认不落日志；调试采样须脱敏且有保留期。告警只在待处理认证、长期卡住、备份失败、磁盘阈值或公开泄漏风险等需要行动时发，不为每个完成任务跨渠道刷屏。

资源验收记录服务器规格、媒体时长/大小、ASR实时因子、模型用量可见范围、CPU/RAM峰值、磁盘增长。没有这些数据不承诺每小时处理多少视频或每月套餐够不够。

## 五、故障手册

### 订阅额度耗尽

停模型调度，保留输入指纹和断点；纯解析/索引继续。等待官方恢复窗口，未知时低频检查。不能改用普通 API；需要扩大成本时才提出明确预算选择。

### 微信资格未具备或回复窗口关闭

标记渠道 unavailable/reply_unavailable，核心任务仍可在 CLI/HTTP 查询；只在已授权同一用户通知设置下走备选，不复制全部材料到 Telegram。不使用私人号 hook 绕过资格。

### 平台解析失效

熔断对应 parser，保留临时链接与错误，允许补贴正文/字幕/截图。锁定新版后在样本集验证才恢复。不能为了“跑通”轮换账号/签名绕过已明确限制。

### Git 冲突或结果不确定

暂停相关 change，读取权威 ref、change_id 和文件 hash 对账；非相关任务可继续。无法证明是否执行就人工维护队列，不重复应用；不 reset/force push。用户真正需要决定的是语义冲突，不是技术重试细节。

### 公开泄漏风险

立即停止新发布并隔离候选产物；已发布范围按实际授权执行回退/下架，并明确第三方缓存可能存在。保留审计证据，修 manifest/资源过滤，复测 E16。不得以自动清理为由永久删除用户原件。

### 数据库/磁盘故障

停止 writer 与后台 mutation，保存日志和存储快照；先恢复一致 DB/Git/对象集合，再重建索引。备份恢复必须在隔离测试目录演练；不能在生产上边运行边直接拷数据库主文件。

### 秘密管理不可用

停止依赖秘密的调用，已有合法短期会话是否续用由明确 TTL 决定；不记录、不导出 root token。按人工解封/灾备流程恢复，轮换后重启缓存旧 key 的宿主并验证旧 token 已失效。

## 六、实施前最终检查清单

此处是执行时填值，不是现在再问一轮：

- 指定服务器、域名、TLS、磁盘与备份目标已可用。
- Git 当前分支/工作区/远端权限确认，用户本地同步策略可回退。
- 实际订阅属于 ChatGPT/Codex、Z.AI 国际版或智谱中国版；资格、provider、限额和正式登录验证。
- 微信客服/公众号主体与 API 权限可用；不满足就延后该通道。Telegram Bot 身份绑定与出站网络验证。
- OpenBao 初始化/解封/工作负载引导身份由管理员完成，恢复资料分开存放。
- 各平台真实验收链接与许可范围选定，存量 publish 映射核对，不批量扩大公开范围。
- 启用真实自动提交和站点发布分别获准，不借文档任务推定生产授权。

## 执行 Agent 任务书

为 E01–E20 建可重复测试和结果模板；测试 mock、fixture 与经批准真实样本分层。提交 feature flag 默认值、kill-point 注入、备份恢复演练步骤、依赖许可清单、上线/回退 runbook。未达到安全/并发/隐私门槛不得以“主要功能能跑”宣告完成。禁止自行启生产、创建凭据、付费、公开数据或按计划自动越过审批阶段。
