# 00 · 范围、决策与复用边界

## 目标与优先级

P0：知枝学习链路继续优化、接入统一知识底座；CLI 智能体能查知识、提交材料、查看任务、处理少量重大决策。
P1：微信分享入口，Telegram 备选；小黑盒和抖音素材优先；服务器持久任务不依赖用户一直打开终端。
P2：检索与可解释学习雷达；传统 Wiki 分类门户。网站不能取代核心产品，也不能为了视觉效果维护第二份正文。

“知枝”是统一产品称呼；旧文档“知返/知反”、源码 ahadiff/growth 不在此阶段批量改名。

## 已确定的设计决定

| 决定 | 采用方案 | 代价和边界 |
|---|---|---|
| 部署 | 个人服务器，单节点起步 | 单机故障需备份恢复，不冒充高可用 |
| 后端 | Python/Starlette 模块化单体 | 沿用知枝生态；不是每模块一个微服务 |
| 正式知识 | Markdown+Git，Obsidian 继续编辑 | 同步与冲突需显式处理 |
| 过程 | SQLite 本地盘，单写进程 | 不把 SQLite 文件挂网络盘或多机共享 |
| 附件 | 私有内容寻址文件目录 | 不塞 Git；媒体和公开资源独立授权 |
| 主交互 | Pi CLI + 薄 extension | 不 fork 终端，不让 Agent 任意 shell/写库 |
| 模型 | 合规使用用户 Codex/GLM 订阅可用路径 | 具体能力和额度通过适配器验证，不默认 API 免费 |
| 密钥 | 自托管 OpenBao，CLI/HTTP；工作负载最小权限 | 解封、初始身份和灾备要人工建立，不能凭空无密钥启动 |
| 采集 | 小黑盒、抖音先做，真实样例验收 | 受官方访问/登录/权限限制，失败支持手工补料 |
| 收藏 | 临时预览后由用户 keep | 不把每个分享自动存入永久 RAW |
| 正式增量 | 常规有来源补充自动；一般问题 AI 复核 | 核心结论翻转、重要合并删除、立场变化、隐私放宽必须人工 |
| 网站 | 现有 Quartz + 确定性投影 | 普通条目默认公开意图，但隐私/权利筛选独立 |

## 不做

不建全能远控中台、多租户 SaaS、独立手机 App；不重写知枝 UI；不先引入向量数据库、图数据库、Kubernetes、Kafka；不承诺私人微信机器人稳定接入；不无限下载平台历史；不把已抓到的内容视为有权公开全文；不通过反代订阅 token 伪装免费通用 API；不把模拟输出当 Demo 验证结果。

## 复用与自研清单

- 保留：现有 Vault Manager 路径和原子写基础、知枝 concept/card/session 标识、knowledge_wiki 托管块/hash 防护、Git 快照、学习流程、Quartz。
- 集成：Pi 终端和 provider、OpenBao、合适的媒体解析器、单一 ASR 实现、官方消息渠道、Markdown/YAML 解析器。
- 自研薄层：稳定 entry_id 映射、来源锚点、跨渠道幂等、候选变更与风险规则、受控 Git 提交、来源到条目/学习证据映射、公开过滤、平台异常回退。
- 暂缓：全文检索不足之前的 embedding；证据不足之前的掌握评分；核心链路跑通之前的重度门户设计。

前序 16 包中 11 包有复用基础，只是分类计数，不能声称 69% 工时节省。新增 Pi/模型订阅与渠道工程应独立估算。

## 方案授权边界

当前只交付文档和概念，实施任务需要单独启动。长期自动入库属于目标产品内部策略；公开发布、凭证配置、账户授权、生产运行须按启动时授权执行。“没有必须本地处理”不等于雇主代码或第三方私人信息可任意上传；系统默认排除密钥、会话、私人附件、工作原始代码、账户标识及未确认传播权内容。
