# 知枝统一知识平台 · 分板块执行方案 v0.3

日期：2026-10-20（UTC+08:00）｜交付性质：设计与后续执行任务书，尚未实施。

## 推荐结论

保留知枝、Markdown/Obsidian/Git、现有 Quartz。个人服务器运行一个 Python/Starlette 模块化领域服务，管理任务、来源、提案、审核与受控提交。Pi CLI 是主要交互；微信优先承接分享，Telegram 为可用性备选；首批内容平台是小黑盒、抖音。LLM Wiki 是知识增量生产流程，不是另一个数据库。网站只是程序生成的传统分类查阅出口。

本轮不制作 Demo，不迁移真实知识，不部署，不创建凭证，不开通付费服务，不发布任何资料。下文所有目录、表、API、阈值均为目标设计，不能当作已存在实现或实测结论。

## 开工顺序

1. 冻结脱敏 fixture 与现状快照，完成 01 的契约和 dry-run。
2. 完成 02 的任务账本、权限、对象存储和事件接口。03 与 04 可用 mock 并行，但不得各建数据库。
3. 优先闭合 05 的知枝学习成果→提案→复核→受控 Git 提交；这是已有能力最短验证路径。
4. 接通 03 的真实订阅身份与 04 的首批平台样例，完成分享→预览→收藏→Wiki 的第二条增长路径。
5. 补 06 的检索和雷达；发布 Adapter 的正确性修复可以独立完成，首页美化不阻塞核心上线。
6. 07 的安全与恢复测试贯穿所有步骤；先影子运行，再小范围自动入库，最后另行开启公开发布。

## 上线条件不是新一轮产品提问

已决定的渠道偏好、服务器位置、首批平台、首页定位、审核原则不再重问。实施时需补齐具体域名/机器规格、官方微信账号资格、订阅登录、秘密初始化、真实验收链接、Git 仓库权限。这些是运行参数和资格检查，不阻塞本方案。资格不足的模块显示 unavailable，其他模块继续执行。
