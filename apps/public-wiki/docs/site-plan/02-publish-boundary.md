# 公开边界

## 总规则

所有公开内容必须显式声明：

```yaml
publish: true
```

没有 `publish: true` 的内容一律不进入线上网站。

## 默认不公开目录

以下目录默认不公开：

- `daily/`
- `output/`
- 大部分 `raw/`

说明：

- `daily/` 是私人每日记录，不能默认公开。
- `output/` 是 AI 生成物和整理报告，不能默认公开。
- `raw/` 是原始输入和待编译素材，不能直接当成公开文章。

## raw 的特殊规则

`raw/` 默认不公开。

只有满足以下条件的文件，才可以进入文章区：

```yaml
publish: true
section: article
```

推荐先经过整理或改写，再公开为文章。

## 明确禁区

以下内容不得公开：

- 账号、API key、密钥、token
- 私人聊天记录
- 私人项目细节
- 情绪记录
- 未完成想法
- 无法确认授权的长篇原文复制
- 含有他人隐私的信息

## 发布前检查

每次发布前至少检查：

1. 是否存在未标记 `publish: true` 却进入站点的页面
2. 公开页面是否链接到不公开内容
3. 公开页面是否含有敏感字段
4. `daily/` 和 `output/` 是否被构建进线上结果
5. `raw/` 是否只发布了明确标记的精选内容

## 推荐实现

第一版使用白名单策略：

```text
只复制或构建 publish: true 的 Markdown 文件
```

不要使用黑名单策略，因为黑名单容易遗漏新目录和新文件。
