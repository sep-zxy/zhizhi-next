# 发布同步流程

## 目标

建立半自动同步流程。

目标不是完全自动发布，而是：

```text
自动检查和生成
人工确认后发布
```

## 推荐命令语义

后续可以固化一个指令：

```text
执行站点同步
```

## 同步步骤

### 1. 扫描公开内容

扫描所有 Markdown 文件，找出：

```yaml
publish: true
```

### 2. 检查 frontmatter

检查公开页面是否包含：

- `title`
- `publish`
- `section`
- `summary`
- `created`
- `updated`

软件页面额外检查：

- `software_id`
- `status`
- `platforms`
- `pricing`
- `open_source`
- `official_url`
- `download_url`

### 3. 检查公开边界

检查：

- `daily/` 是否被公开
- `output/` 是否被公开
- 未标记的 `raw/` 是否被公开
- 公开页面是否链接到私有页面
- 公开页面是否包含敏感字段

### 4. 检查链接

检查：

- wikilinks 是否能解析
- index 链接是否存在
- 软件 related 是否指向真实文件
- 公开页面引用的图片是否存在
- 图片是否来自允许公开的位置

### 5. 处理图片和附件

处理：

- 扫描 `publish: true` 页面中的图片引用
- 解析 `![[image.png]]` 和 `![alt](path/image.png)`
- 只复制被公开页面引用到的图片
- 阻止 `daily/`、`output/`、私有截图或敏感图片进入构建结果
- 输出缺失图片和疑似私有图片报告

### 6. 生成索引

生成或更新：

- Wiki 导航
- 软件库总览
- 最新内容列表
- section 索引

### 7. 构建站点

运行 Quartz 构建命令。

### 8. 输出报告

报告必须包含：

- 本次公开页面数量
- 新增公开页面
- 更新公开页面
- 缺失字段
- 断链
- 缺失图片
- 被复制的公开图片
- 被阻止公开的文件
- 是否可以发布

### 9. 人工确认发布

确认后再执行：

```text
git push
```

或触发部署平台自动构建。

## 安全原则

构建脚本应使用白名单逻辑。

优先：

```text
只处理 publish: true
```

避免：

```text
复制整个 Vault 再排除私有目录
```
