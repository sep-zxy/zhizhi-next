# 实施路线

## 阶段 0：规则确认

目标：确认公开内容规则。

任务：

1. 确认 `publish: true` 是唯一公开入口
2. 确认 `daily/` 和 `output/` 默认不公开
3. 确认 `raw/` 默认不公开
4. 确认 section 枚举：

```yaml
section: wiki | software | blog | article | app-note
```

完成标准：

- 公开边界写入项目文档
- 后续脚本按白名单逻辑设计

## 阶段 1：Quartz 首版站点

目标：跑通可访问、可搜索的 Wiki 发布。

任务：

1. 初始化 Quartz
2. 配置内容源或内容同步目录
3. 实现 `publish: true` 内容筛选
4. 发布部分 wiki 页面
5. 处理公开页面引用的图片
6. 配置搜索、backlinks、graph
7. 完成第一次本地构建

完成标准：

- 本地可构建
- 首页可访问
- Wiki 可搜索
- 未公开内容没有进入构建结果
- 公开页面引用的图片能显示

## 阶段 2：软件库样例

目标：建立软件库结构。

任务：

1. 新建 `notes/software/`
2. 编写软件 frontmatter 模板
3. 创建 3-5 个软件样例
4. 生成 `/software/` 总览页
5. 建立软件详情页和相关内容链接

完成标准：

- 软件库总览可访问
- 软件详情页可访问
- 软件字段完整

## 阶段 3：栏目入口

目标：建立博客、文章、应用笔记的公开入口。

任务：

1. 新建或确认 `notes/blog/`
2. 新建或确认 `notes/apps/`
3. 定义 `section: blog`
4. 定义 `section: article`
5. 定义 `section: app-note`
6. 首页加入栏目入口

完成标准：

- 栏目结构存在
- 没有误公开未成熟内容
- 可以逐步补内容

## 阶段 4：半自动同步

目标：固化 `执行站点同步`。

任务：

1. 扫描 `publish: true`
2. 校验 frontmatter
3. 检查公开边界
4. 检查断链
5. 检查图片引用
6. 复制公开页面实际引用的图片
7. 生成软件库总览
8. 生成最新内容
9. 构建 Quartz
10. 输出同步报告

完成标准：

- 每次发布前有检查报告
- 构建结果可重复
- 人工确认后再推送部署

## 阶段 5：前端增强

目标：在发布闭环稳定后提升视觉和交互。

推荐方向：

```text
Astro 或 Next.js
Tailwind CSS
shadcn/ui
```

优先增强：

- 首页
- 软件库卡片
- 软件筛选
- 最新内容
- 标签入口

完成标准：

- 不破坏 Quartz 阶段的内容规则
- 不降低公开安全性
- 软件库浏览体验明显提升
