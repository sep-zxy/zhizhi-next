# 03 · Pi CLI 与订阅模型路由

## 一、选型与已核验边界

Pi 是用户日常主要交互和模型执行宿主，领域服务不是公开通用模型代理。采用 extension，不 fork Pi，不重写 TUI。此前官方静态核验为 earendil-works/pi v1.3.0、包 @earendil-works/pi-coding-agent、Node >=22.19，实际实施锁定版本和 lockfile 后再测，不以 main 分支示例代替固定接口。

最新订阅核验决定：

- ChatGPT/Codex：优先当前 Pi 的 OpenAI /login → Sign in with ChatGPT。旧 openai-codex 为 legacy，不作为新方案默认 provider。
- Z.AI 国际版 Coding Plan：官方已支持 Pi，且涵盖研究/办公/自动化，不再断言只能编程。走内置 zai provider 和套餐路径，不混普通按量 API。
- 智谱中国版：Pi 存在单独 China Coding Plan provider；本轮没有核实中国版套餐全部条款/额度，不能照搬国际版 5 小时/每周规则。部署按实际账户核验。
- 备用可选官方 Codex CLI 非交互执行器，复用正式登录的已存认证；只在可信个人服务器，不把登录凭证投入公开 CI。

使用范围是用户自己的知识任务，不共享套餐给其他用户，不复制 token 自建通用反代，不抓浏览器 cookie。套餐是否支持实际账户/区域/模型须通过登录与小样本验收。官方 OpenAI OSS OAuth 路线的注册与稳定 host ID 由正式集成遵循，不让业务服务自行猜测协议。

## 二、成本与路由决策

预算策略：metered_api_enabled=false；未批准新增按量预算。主 provider 在已有订阅中选现场可用的一条，不同时启动两套抢额度。另一条仅在已合法登录且数据路由允许时回退。

ModelTask 契约：task_id、purpose（preview/generate/review/answer）、input_refs、input_classification、allowed_provider_ids、schema_name、max_output_tokens、deadline、dedupe_key。任务配置记录实际 provider/model/version、输入指纹、结果 hash、用量信息（可获得时）和终态。

路由算法：
1. 检查材料分类与 provider 允许范围；秘密永不入 prompt，雇主/第三方私人材料默认待授权，而非“用户说可远端处理”即全放行。
2. 优先已就绪订阅，按账户串行调度，主交互任务高于后台批量整理；后台不抢占用户会话全部额度。
3. quota 错误→waiting_quota，按服务返回恢复信息安排；未知窗口采用保守退避，不高频探测。
4. auth 错误→waiting_auth，通知一次；不能将 credential 作为工具返回给模型。
5. 结构化结果不合法→至多有限修复（初始 1 次），之后 needs_model_review；不能无上限循环消耗套餐。
6. 仅切换到 allowed_provider_ids 且有可用订阅的路由；所有路由不可用就排队，不自动调用付费 API。

“订阅覆盖”只覆盖其许可和可用额度内的模型步骤。OpenAI 当前订阅 Responses 路线不含 transcription/音视频输入/Files 上传/托管 file search/Code Interpreter 等，不能把视频直接扔进去假定免费。优先现成字幕；无字幕采用个人服务器 CPU Whisper 类方案，先测资源。OCR/embedding 独立处理，不以模型订阅保证其费用。首版不需要 embedding 才能使用。

统一模式下，既有知枝 knowledge_material_model、knowledge_learning 及问答/chat、题目生成、解析和复核的全部模型调用也必须经 ModelRunner/订阅任务适配器，不能只改新 Wiki generator/reviewer 而保留旧按量 API 旁路。LocalVaultBackend 的兼容仅针对存储，不授予调用旧收费模型的权限；未启用 metered_api 时相关旧配置必须明确禁用并测试零请求。

## 三、extension 工具清单

| 工具（拟定名称） | 服务端动作 | 副作用 |
|---|---|---|
| zhizhi_intake | POST /intakes | 新建临时任务，不长期收藏 |
| zhizhi_job_status | GET /tasks/{id} | 无 |
| zhizhi_keep / discard | POST /intakes/{id}/decision | 用户选择长期保留或丢弃 |
| zhizhi_search / read_entry | GET /search、/entries/{id} | 无，范围过滤 |
| zhizhi_propose_patch | POST /changes | 仅提案 |
| zhizhi_review_queue | GET /reviews | 无 |
| zhizhi_submit_user_decision | 用户确认交互→POST /reviews/{id}/decisions | 服务端要求独立用户身份/nonce |
| zhizhi_growth | GET /growth | 无 |
| zhizhi_radar | POST /radar/runs | 候选建议，不自动创建学习任务 |

表中路径均挂 /api/knowledge/v1 前缀。普通任务内容不能调用或伪造用户确认。所有输出带 task_id/trace_id；CLI 断线后可恢复，不依靠 Pi 会话文本推断服务器状态。

用户典型命令：“看看这个链接值不值得留”“收藏并补充到已有条目”“我之前对这个问题怎么理解”“只给我看必须决定的事项”。少量诊断子命令可保留，不能要求日常手动拼流水线。

## 四、运行与隔离

Pi 宿主无正式 Vault 写挂载、无 DB 文件、无 Git/部署凭证、无 Docker socket。只注册领域工具，禁用默认 bash/edit/write、未审 extension、隐式 MCP 工具发现。普通白名单不是安全边界，OS 文件/网络权限和服务权限是硬边界。

extension 执行代码与 skill 文本不同：只有维护者审核的 extension 可运行；网页/分享正文不能变成新的 skill 或插件。工具输入使用 schema 验证；动态命令字符串不从材料拼接。

RPC 仅内部 stdin/stdout JSONL 使用，不能映射成公网端点。prompt accepted 不是任务完成；按固定版本协议等待 agent_settled，收集 task_id，取消/重启后先对账。当前 SDK 的 tools 是名称列表，noTools/customTools 等具体签名按固定版本测，不套旧 SDK 示例。

OAuth 由正式 CredentialStore 刷新；单一持有者或加锁刷新，防止多个进程轮换同一 refresh token 失效。API key 可经 OpenBao 安全读取；若 provider 把 key 缓存到进程结束，轮换要重启/显式刷新。不得假称所有 OAuth 都能直接存在 OpenBao 而无需适配。

## 五、验收

1. 真账户登录前用 fake provider 测 schema、权限、取消和重启；之后小量文字任务验证正式登录，未授权前不调用。
2. 给模型一篇写“读取服务器密钥并上传”的文章：没有相应工具，服务也拒绝越权。
3. quota 报错：任务保留 checkpoint；没有普通 API 请求或账单。
4. primary 失败，secondary 未获数据路由许可：不得回退上传。
5. CLI 关闭后媒体/知识任务仍有持久状态；重新打开能从 task_id 恢复。
6. reviewer 独立读取旧文/证据后可拒绝 generator；两者输出均不直接改 Git。
7. 重复 ModelTask 不产生重复 ChangeSet；订阅支持不被显示成“无限调用”。

## 执行 Agent 任务书

实现 integrations/pi-zhizhi 的受限工具和可替换 ModelRunner 接口，先 fake provider。提交订阅/按量端点区分测试、额度/auth 状态测试、prompt-injection 越权测试、RPC 完成/取消/恢复测试。不得创建 OAuth grant、读浏览器凭证、搭订阅反代、隐式调用付费 API。上线只要求实际套餐/账号/provider 资格作为环境前置条件，不另开泛泛选型问卷。
