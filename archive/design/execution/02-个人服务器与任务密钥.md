# 02 · 个人服务器、领域服务、任务与秘密管理

## 一、物理部署选定

单台 Linux 个人服务器，Python/Starlette 领域服务 + 独立轻任务 worker + 私有媒体 worker + 受限 Pi 运行实例。不是四套业务后端：使用同一领域契约和任务账本。优先沿用现有 TaskRunner；只有它无法满足持久 lease、重试与恢复时，才换成轻队列实现。队列框架不能代替业务幂等。

建议服务角色与权限：

| 角色 | 可读 | 可写/调用 | 禁止 |
|---|---|---|---|
| ingress | 平台回调元信息 | submit_intake、消息回执 | 正式库、Shell、模型秘密 |
| domain | 过程库、授权来源 | SQLite 单写连接；任务、策略 | 任意系统目录 |
| media | 指派的临时输入 | 本任务缓存、结果上报 | Vault、订阅令牌、内网 |
| agent | 检索 API、任务 API | propose 等领域能力 | bash/edit/write、DB、Git、Docker socket |
| writer | 受控 Vault/Git、审查记录 | CAS 提交、提交回执 | 入站公网、模型调用 |
| publisher | public staging | 指定站点产物 | RAW、私有索引、整库 |

worker 通过领域服务更新任务，不开各自 SQLite 写连接。writer 的 Git 写权限与 DB 状态请求分开；域服务是账本权威。最小起步可同一部署包不同进程，不能因为同机就给相同 uid 和全盘挂载。

## 二、目标存储布局

以下为拟部署路径，不是当前已有服务器目录：

```text
/srv/zhizhi/config/             # 非秘密版本配置
/srv/zhizhi/state/platform.db   # 本地盘 SQLite，单写进程
/srv/zhizhi/vault.git/          # 服务端权威 Git 仓库
/srv/zhizhi/worktrees/          # writer 隔离临时工作区
/srv/zhizhi/objects/sha256/     # 收藏后私有对象
/srv/zhizhi/cache/intake/       # 临时预览/未收藏素材
/srv/zhizhi/public-staging/     # 已筛选投影，发布器唯一输入
/srv/zhizhi/releases/           # 确定性站点产物
```

SQLite 开启 WAL、foreign_keys、busy_timeout，并选耐久优先同步策略；使用 backup API 备份，不直接复制运行中主文件忽略 WAL。备份包括数据库一致快照、Git refs/bundles、对象清单与实际对象。索引不必保存，但重建耗时要测。对象落盘先临时文件、计算 hash、fsync、原子 rename，再登记可用；孤立对象由保留期任务回收，不能删除有引用的原件。

## 三、任务状态机

Task={task_id,type,owner_id,input_ref,input_hash,state,attempt,max_attempts,next_run_at,lease_owner,lease_expires_at,cancel_requested,output_ref,error_code,created_at,updated_at,version}。

queued → running → succeeded / partial / waiting_user / waiting_auth / waiting_quota / retry_wait / blocked / failed / cancelled。

- claim 必须原子 CAS：仅 queued 或到期 retry_wait 可被领取；lease 过期不等于工作没执行，重新领取前对账结果副作用。
- 每个任务副作用绑定唯一 operation_id；重复请求返回同一副作用。下载重复可幂等，正式提交必须核对 Git change_id。
- 失败分类：网络超时可退避重试；登录/CAPTCHA/访问拒绝进入 waiting_auth 或 blocked，不无限重试；额度不足进入 waiting_quota，不付费降级。
- 初始建议每个外站 host 并发 1、媒体任务并发 1、模型任务并发 1，测量后再调；配置是保守起点不是容量承诺。
- 进度通过 task_events(seq,task_id,stage,summary,created_at) 和 GET /tasks/{id}/events?after=seq 读取，可选 SSE。消息仅发受理/预览/终态或需操作事件，避免每秒打扰。
- cancel 终止后续处理；已经提交的知识不假装取消成功，返回 committed 和对应回滚入口。

Task 是执行状态，不等于 Intake 或 ChangeSet 业务状态。Intake awaiting_keep、needs_input 映射 Task waiting_user；waiting_model 表示依赖模型步骤，按原因映射 queued / waiting_auth / waiting_quota，不另造 Task 枚举；ModelTask needs_model_review 映射当前 Task partial，并创建独立审阅任务，不能让机器错误占满用户队列；needs_auth 映射 waiting_auth；rate_limited 映射 retry_wait；unsupported 映射 blocked；ChangeSet needs_user 映射 waiting_user，needs_evidence 可结束本轮 Task 为 partial；ChangeSet reconcile_required 映射 Task blocked，维修对账成功后才恢复相应步骤。失败不是隐式业务回滚，Task succeeded 也不表示已发布。

状态和通知在同一 DB 事务写入 outbox，发送后记录 channel_message_id；不将消息发送成功当处理成功。结果不确定先核对平台回执，不能盲目重复发送。

## 四、OpenBao 秘密托管

选择自托管 OpenBao 作为机器秘密管理服务（CLI 与 HTTP API），不是把密钥写 .env 提交 Git。单节点起步即可，但必须理解它自身也是恢复对象。

秘密分域：model/{provider}/{account}、channel/{wechat|telegram}、git/{writer}、publish/{target}。访问策略按服务角色、环境与路径分隔，token 短期、可撤销、只读或限定操作，不给应用 root token。

### 启动与解封的真实边界

1. 由管理员建立 TLS、初始化和恢复资料；解封/恢复份额离线分开保管，不存同机单一脚本里。
2. 首版选择人工解封，重启后等待管理员；服务等待秘密可用，不降级把密钥写明文。暂不承诺无人值守自动解封。
3. 自动解封以后需要独立的自托管可信密钥服务/HSM 等，必须另做架构与恢复评估，不把解封 key 放本机就称为安全托管。
4. 创建工作负载身份时由管理员一次性认证；若用 AppRole，受保护的引导 SecretID/短期凭据仍须安全交付和轮换，OpenBao 不消除引导秘密问题。
5. 通过受保护临时文件/内存交付必要凭据，限制文件权限和生命周期；日志、进程参数、诊断接口均不回显 token。OAuth 续期令牌交由对应官方登录流程管理，是否可外置到 OpenBao 要验证适配器支持，不能擅自抓取或改造认证格式。
6. OpenBao 自身备份、解封资料和应用数据库备份分离；做一次恢复演练才认为可用。

选择依据是自托管和机器接口需求；许可证、镜像签名、版本固定和安全公告须在实施锁定时记录。官方参考：https://openbao.org/docs/ 、https://github.com/openbao/openbao 。

## 五、身份与网络

公开仅开放 HTTPS 入口和必要渠道回调。SQLite、OpenBao、Pi RPC、writer 均不暴露公网。服务间使用受限身份；个人客户端从受保护入口认证。未知用户的微信/Telegram 消息不允许调用领域写操作。

Webhook 校验签名/secret、时间窗口（协议支持时）、事件 ID 防重放，并映射平台发送者到唯一 owner；不能用消息里写“我是主人”绑定身份。一次性绑定由已认证管理端确认。

入站 URL 抓取先解析 DNS，再限制每次重定向，阻止 localhost、RFC1918、链路本地、云元数据和非 HTTP(S)；下载流限制大小、时长、类型，重解析避免 DNS rebinding。媒体解析器沙箱无服务凭据。平台正文永不作为 shell 命令/动态 Python 执行。

## 六、验收与运行参数

- DB/worker 重启：任务状态仍可查询，lease 回收后没有第二次提交。
- OpenBao sealed：模型和渠道返回 waiting_auth，不泄露、不从日志恢复秘密。
- media 下载恶意重定向到 169.254.169.254：阻断且无请求抵达目标。
- Agent 尝试访问 Vault、Docker socket、秘密文件：OS 与 API 双重拒绝。
- 接收合法重复回调：只创建一个 intake，回执引用同一 task_id。
- 备份在干净测试目录恢复：entry/source/task 引用可对账，索引可重建。

实施参数清单：域名/TLS、服务器内存磁盘、用户 uid、路径、备份目的地、OpenBao 初始化方式、允许模型域名/路由、平台 sender 映射。此处不需要再由用户做产品选择。

## 执行 Agent 任务书

在获准的开发环境实现领域服务和 mock workers，不触碰生产服务器。提交配置模板（只有占位符）、进程权限表、Task 状态迁移测试、SSE/轮询恢复测试、备份恢复脚本设计和秘密 bootstrap runbook。不得安装生产凭证、暴露 RPC、将 OpenBao root token 写配置、改网络安全设置或开启真实采集。报告所有需要管理员执行的一次性步骤。
