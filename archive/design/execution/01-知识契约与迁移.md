# 01 · 知识契约、来源与兼容迁移

依赖：现有 SCHEMA v5、Vault Manager、知枝 schema v31 快照。目标是保留大基础、更新细则，不复制旧规则所有历史限制。以下 v6 是拟议版本号，实施前先检查是否已有更新版，禁止覆盖后来的版本。

## 一、事实源及最小字段

正式正文在 Markdown/Git；任务与审批在 SQLite；原始媒体在私有对象目录；索引可重建。SQLite 中 entry_catalog 只有路径、版本、可见性和索引摘要，不成为另一份可编辑正文主库。

正式 fixture 使用下列完整结构（示例 ID 非真实资产）：

```yaml
schema_version: 6
entry_id: ent_example_001
title: 事件溯源
aliases: [Event Sourcing]
type: concept
status: stub
created: '2026-10-20T00:00:00+08:00'
updated: '2026-10-20T00:00:00+08:00'
categories: [软件工程]
tags: [架构]
sources: [src_example_001]
visibility: public
```

type/status 可用值以现有注册表为基线做兼容扩展，示例不是强行替换其枚举。公开状态不是仅由 visibility 决定：public 代表发布意图，发布资格还必须通过来源、正文和资源检查。迁移优先映射现有明确 publish:true/false 和已生效公开策略，保留既有意图；仅无明确旧标志/策略、无法判定的条目标记 legacy_unclassified，不自动发布。新 Wiki 常规条目可默认 public 意图；新收件流水线 RAW/会话/提案默认 private。旧 RAW/Wiki 若有既定默认公开规则，必须记录并保留映射，不能静默重分类存量原件；权利/隐私异常独立挂起核查，不自动扩大披露。

规则：entry_id 永久稳定、文件重命名不变；标题不作主键；created 不随重编译刷新；updated 只在实质正文/来源/关系变化时更新；换行、生成索引更新不能伪造增长。保留用户自定义未知字段，禁止迁移时静默丢弃。正文不强制填空白“我的理解”。

## 二、来源契约

SourceDescriptor 存在版本化私有来源目录（建议 .knowledge/sources/*.json；不对公网发布），大对象用 hash 引用：

```json
{
  "source_id":"src_example_001", "schema_version":1,
  "origin":{"platform":"douyin","original_url":"https://example.invalid/share/1","canonical_url":null,"external_id":"fixture-1"},
  "captured_at":"2026-10-20T00:00:00+08:00",
  "content_sha256":"fixture-content-hash",
  "extractor":{"name":"fixture","version":"1"},
  "coverage":{"title":true,"text":true,"subtitles":false,"audio_transcript":false,"comments":false},
  "completeness":"partial",
  "visibility":"private", "rights":"unknown",
  "model_route_policy":"public_source_allowed",
  "objects":[{"sha256":"fixture-object-hash","mime":"text/plain","role":"extracted_text"}]
}
```

URL 存储前移除一次性 token、账号参数；确需原 URL 时按敏感字段私有保管，公开引用用清洗版本。Source 创建后原件不覆盖；重抓取得新 revision/hash，来源 ID 可保持同一内容身份。来源可定位必须到具体段落、页码或时间区间：EvidenceRef={source_id,source_revision,locator,claim_ids}。只有标题/封面时不得声称总结完整视频。

Source 与 Entry 是多对多；一个素材可支持多条知识，一条知识可引用多个材料。重复来源不自动创建新条目。

## 三、关键过程对象

- Intake：intake_id、owner_id、channel、external_message_id、input_hash、status、preview_revision、expires_at；UNIQUE(owner_id,channel,external_message_id)。无消息 ID 用客户端 idempotency_key。
- ChangeSet：change_id、entry_ids、base_git_revision、base_file_hashes、patch、patch_hash、evidence_refs、origin、risk_flags、policy_version、state、idempotency_key。
- Review：review_id、change_id、patch_hash、base_git_revision、actor_type、actor_id、result、reason_codes、evidence_refs、reviewer_model、policy_version、created_at。AI 无权伪造 actor_type=user。
- LearningOutcome：origin_device_id、concept_id、card_id、session_id、outcome_revision、evidence、user_statement_refs。幂等键包含设备、session 和成果版本，不能仅按 concept 去重掉后续学习。
- Relation：relation_id、from/to entry_id、type、evidence、status=candidate/confirmed/rejected、asserted_by。导航双链不自动变成 confirmed 学习关系。
- GrowthEvent：event_id、change_id、entry_id、type=entry_created/substantive_updated/source_added/relation_confirmed、committed_at、public_projection_allowed。

正式关系建议按条目写私有 Git sidecar .knowledge/relations/<entry_id>.json，公开子集单独生成；相同 Git revision 可重建关系索引。

## 四、API 共同契约

新路由统一 /api/knowledge/v1；旧路由通过适配而非无通知破坏。mutation 带 Idempotency-Key；返回 {data,task_id,trace_id}；错误 {error:{code,retryable,detail},trace_id}。建议错误码：AUTH_REQUIRED、SCOPE_DENIED、SOURCE_INCOMPLETE、BASE_STALE、REVIEW_REQUIRED、ROUTE_UNAVAILABLE、QUOTA_WAIT、POLICY_BLOCKED。

同一个身份+endpoint+幂等键的请求体 hash 相同返回原结果，不同返回 409 IDEMPOTENCY_CONFLICT。所有读写服务端过滤 owner/scope，不能让客户端传 owner_id 冒充身份。文件路径仅在服务端从 entry_id 解析，禁止模型指定任意绝对路径。

## 五、迁移流程

1. 枚举指定 Vault，不遍历用户整台电脑；只读清点目录、Schema、未知字段、旧 sources、concept/card ID、托管块、链接。
2. 导出 migration-plan.json：原路径/hash、建议 entry_id、映射项、歧义、迁移前后差异；零真实写入。
3. ID 映射持久化后再次 dry-run 必须完全一致；不每次生成新 UUID。重复 ID 停止相关条目；同标题不同语义不合并。
4. 旧 sources 逐条变 SourceDescriptor，同时兼容旧链接；保留来源顺序与引用可读性。标记无法定位来源，不捏造证据。
5. 将知枝 growth_concept_id/card_id 与 entry_id 写映射表，保留原字段读取兼容和托管块。
6. 复制脱敏 fixture 试迁移→验证→再验证往返读取与迁移幂等；输出损失检测报告。
7. 实施时备份 Git 与数据库；只对批准范围执行、每批独立提交。读旧写新，稳定后才移除兼容层。

不可逆旧字段丢失不允许。回滚为对应迁移提交的补偿变更，保留迁移后的用户编辑，不能 reset 整库。

## 六、验收

| Given / When | Then |
|---|---|
| v5 文件含未知字段、中文和带引号日期；迁移 | 字段/原文保留、日期类型正确、无伪新增 |
| 相同迁移计划重复运行 | ID 和输出 byte/hash 不变，无额外提交 |
| 同标题两条不同概念 | 保留独立身份并报告，不能自动合并 |
| Wiki 改名且知枝引用旧路径 | entry_id 查到新路径，concept 映射不丢 |
| 来源只取得元数据 | completeness=partial，不能形成正文事实补充 |
| 旧文件无公开字段也无既定旧策略 | 标记未分类、不进入 public staging，普通读取仍可用 |

## 执行 Agent 任务书

实现 contracts/validator 和 migration dry-run，不迁移真实 Vault。读取 SCHEMA 与注册表后提交字段映射 ADR；写至少上述六类 fixture 测试。报告旧来源/未知字段/托管块是否无损。禁止重命名旧资产目录、按标题合并、删除未知字段、以新 API 替换旧桌面路由。输出 OpenAPI/JSON Schema、迁移报告样例、测试结果和实际源码触点。
