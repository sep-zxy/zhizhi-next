# 06 · 检索、学习雷达与确定性 Wiki 发布

优先级：知识检索 P0，雷达 P1，网站阅读 P2。网站以维基百科式分类门户满足查阅，不继续占用大量设计讨论。

## 一、检索不依赖向量数据库起步

首版复用 SQLite FTS5/现有全文能力，追加标题、aliases、分类与稳定 ID 查找。中文分词/tokenizer 必须用实际查询集测，不假设默认英文分词能做好中文。先以分词或字符 n-gram 的可重建索引验证召回；不为追逐模型引入额外 embedding 成本。

GET /search?q=&scope=wiki|sources|learning&limit= 返回 entry_id、revision、matched_section、snippet、evidence_refs、content_kind、visibility。正式 Wiki 默认优先；私人 RAW 与学习过程只有身份允许才查询。正文与索引 revision 不一致时显示 stale_index，并回源读取或重建，不能返回混合旧版本却不标明。

回答路径：检索→读取对应版本最小片段→模型组织答案→附来源与个人表达归属。检索结果为空时明确“库内未找到”，不能把模型常识包装成已有个人知识；外部补充必须另标，是否入库仍走提案。

## 二、关系与雷达

关系三类分开：导航 wikilink；证据确认的知识关系；AI 候选关系。索引从 Markdown 与版本化 sidecar 重建，不形成隐藏主库。

RadarSuggestion={suggestion_id,target_entry_ids,reason,evidence_refs,relation_hypothesis,proposed_exercise,expected_artifact,state,created_at}。state=proposed/accepted/rejected/snoozed/completed。少量推荐，默认每次最多 3 条；已拒绝的相同证据建议不重复打扰，除非有新证据。

推荐条件可包括：已有两个技术组件但中间机制未有条目；用户刚完成的实践与既有知识有可验证联系；条目明确标注的待证疑问。孤岛只作探索线索，不判定能力不足；关系数、页面数、答题完成率不变成掌握分。

用户接受 suggestion 后，由受控接口创建知枝学习任务，并保存 suggestion→learning_id 映射。重复接受只创建一个任务。完成学习后通过 05 提交成果，更新原条目/关系及 suggestion 状态。仅完成任务不足以确认该关系正确，仍需证据与复核。

## 三、发布应修现有 Adapter，不再造网站

审计指出 sync-site.ps1 已存在转换层，问题是手写 YAML、日期排序、普通条目 /index 化及来源整体删去。优先修这些断点，不宣称从零补一个从未存在的 Adapter。

目标函数：build_projection(git_revision,policy_version,template_version) → staging + manifest。输入固定、输出确定；禁止调用 LLM。Quartz 只读取 staging，不挂载 Vault/RAW。静态模板生成分类入口、条目目录、来源、反链和最近实质修订。

流程：
1. 从指定 Git revision 导出允许范围快照；真正解析 YAML 和 Markdown，校验正文/附件/引用关系。
2. 结合旧 publish 标志与迁移映射生成 publication_intent，不篡改原有公开决定。
3. 分别计算正文、来源引用、附件、图谱、搜索摘要的公开资格。未知资格先隔离相关内容，不批量更改原资产标签。
4. 普通条目映射唯一 slug；分类/目录索引用独立类型，避免普通条目丢右栏、目录和反链。
5. 生成 public staging；检查所有链接/资源必须在 manifest allowlist，不能靠把隐藏页面链接删掉掩盖资源泄漏。
6. Quartz 构建，在产物中再次扫描禁用内容指纹、私有路径、秘密格式及不可公开元信息。
7. 构建和部署分开。仅在获得发布授权并通过检查时切换站点产物；失败保留旧站点。

PublishManifest={revision,policy_version,template_version,pages:[entry_id,slug,content_hash],assets:[hash,path],excluded:[private_internal_reason_ref],source_projection_map,counts,build_hash}。public 版本不能含 excluded 私人标题/原因，内部清单与公开清单分离。

## 四、默认公开的保守实施

“默认公开”作用于新合格 Wiki 知识产物的意图。密钥、账号凭据、私人会话、学习原始答题记录、雇主源代码、第三方私人信息和原始大媒体不自动公开。新流水线 RAW 默认私有建议不追溯改写已有明确 publish:true 资产；已有公开标志保留，权利/隐私异常进入独立检查，不静默全库重分类或重新发布。

允许公开来源可显示清洗后的 URL 与标题；私人来源若公开正文无法脱敏/无法合理佐证，先保持私有/挂起，不把来源删掉后就宣称公开合规。AI 发现隐私风险可以收紧候选的发布资格，但不得自行放宽私有→公开。

首页最小结构：搜索、分类树/专题入口、各分类代表条目、最近新增/实质修订、站点说明。无巨大营销 banner、无伪装业务核心的仪表盘。数量全部从 manifest/GrowthEvent 算，不硬编码“加4”；已审计 106源文件/102叶页/59Wiki/113生成文件是不同口径，不能合并成同一统计。

## 五、验收

- Given 同一 commit/配置/模板，When 断开全部模型并构建两次，Then staging 内容 hash 一致；构建时间戳单列，不污染内容 hash。
- Given 普通条目含带引号日期、嵌套 YAML、中文标签，Then 字段保留且正确排序，不被映射为文件夹首页。
- Given 私有来源支撑可公开摘要，Then 原件/私人文件名不进入 sitemap、搜索索引、图谱或附件目录；必要的公开引用采用独立映射。
- Given 只有格式变化，Then 最近增长不生成“新增知识”。
- Given 用户查询个人理解，Then 区分用户原话与 AI 知识整理，不混作个人立场。
- Given 同一雷达建议两次接受，Then 一条知枝任务；拒绝后无新依据不再反复推荐。

## 执行 Agent 任务书

优先做索引契约、中文查询 fixture 与 manifest 构建，再修现有发布脚本，最后补简单分类门户。不得改网站品牌大设计、引新 CMS/向量数据库、公开真实资料、调用模型生成发布正文或用页面数替代知识价值。交付无模型构建测试、私有内容泄漏回归、日期/标签/来源旧缺陷 fixture，以及雷达→学习→回填的 mock 闭环。
